## 正文

各位好，我是 [你的名字]，平时做 CRM 和商城这块的测试，也搞自动化。

今天不科普 AI 是什么，我就讲一件事：**我咋把 AI 塞进测试日常工作里的**——而且不是 PPT 里写写，是仓库里真有代码、Jenkins 真在跑。

（停顿）

要是你们只记一句话，记这个：

**AI 适合干重复的、格式化的活；测什么、算不算过，还得人说了算。**

---

好，先说说为啥要用 AI。

我做测试最烦四件事：写用例慢、搭自动化慢、回归点不过来、出了问题跟开发产品扯皮说不清。

写用例这事儿，产品给个需求，我得拆场景、标优先级、想边界，弄成 Excel，半天没了。自动化吧，登录、token、断言、报告，样板代码一堆。回归更不用说了，版本一多，纯手工根本扛不住。要是没截图、没接口日志，开发说「我这边是好的」，产品说「用户说坏了」，中间就尬住了。

后来我试了一圈，网页 ChatGPT、Copilot 都用过，最后主力是 **Cursor**。为啥？因为它能看整个项目，改好几个文件，还能帮我在终端跑 pytest。说白了，不是 AI 多聪明，是它能**进你的工程上下文**。

---

我现在的做法，就一条链路，你们记这张图就行：

**需求 → 结构化 → Excel 脑图 → 自动化代码 → 跑起来 → Jenkins 定时 → 出报告。**

我项目叫 Pyautotest，Playwright 加 Pytest 加 Allure，再加 Jenkins。

---

**第一段：需求怎么用 AI 变成用例。**

这个我觉得产品同事也能听进去。

比如 CRM3.13、客户基础信息优化、线索看板这些需求，我以前手写 Excel。现在是：把用例按模块、场景、步骤、预期，写进一个叫 `cases_crm313.py` 的数据文件——听着像开发干的活，其实就是把需求拆成一行行结构化数据。

然后跑一个脚本 `generate_crm313_test_artifacts.py`，自动出 Excel 和 XMind 脑图。

AI 在这儿干啥？帮我**扩边界**。比如外呼手机号解绑，人会想到「点了有没有二次确认」；AI 还能帮你补「未绑定的不显示解绑按钮」「弹窗文案要带真实号码」这种。我已经在九个左右的需求上复用这套模式了。

但重点啊，**AI 出的是初稿，不是终稿**。业务规则对不对、优先级咋定、有没有漏跨模块的场景，必须人审。以前是「从零写」，现在是「审一遍」，快很多。

给产品同学提个醒：需求里要是把异常规则写清楚，AI 扩出来的用例质量会高一大截。需求模糊，AI 也模糊。

---

**第二段：用例怎么变成能跑的自动化。**

开发同事这段可以多听两句。

接口这边，我有七个 API 测试文件，创建线索、认领、分配、移公海、活动记录啥的；另外还有一份 `test_api_negative.py`，专门测异常，十一类：错密码、没 token、缺字段、空 ID 之类。

这类 negative 用例格式特别固定，**最适合 AI 批量写**。我给它看现有文件，说「照着这个风格再加一条」，它写得挺快。但什么算成功、什么算失败，比如 CRM 成功是 code 等于 1000，这个得我自己盯，AI 会猜错。

UI 这边，易食包和 ePak 商城有定时巡检：登录、逛首页、点商品、看详情，失败了有截图和 JSON 报告。这块 AI 主要帮写页面步骤，稳定性还得自己调。

---

**第三段：怎么变成团队都能用的东西。**

本地能跑不算本事，**CI 里能跑才算资产**。

CRM API 回归有个 bat 脚本，Jenkins 一调就行，还能选跑不跑异常用例，完了出 JUnit、发邮件。易食包 UI 是每三十分钟跑一轮，截图归档。

好处是啥？失败了别光说「坏了」，打开报告，第几步、哪个接口、长啥样，一目了然。扯皮少很多。

---

接下来说实话，踩过的坑。

第一，**AI 会瞎编**，字段、选择器都可能编的。对策：让它先读现有代码，改完马上 pytest 跑一下。

第二，**别一次让它改一堆**。我早期说「帮我把 CRM 全测了」，diff 巨大，根本 review 不了。现在一次就一个文件、一个场景。

第三，**别盲信工具报告**。我试过 TestSprite，它老想检测本地端口，我们 API 在远程测试环境，对不上。工具得和 pytest 交叉验证。

第四，**别把账号密码贴进对话**。走 `.env`，走 Jenkins 凭证。

四条原则，记这四个词就行：**初稿、上下文、小步、模板化**。能做成脚本的别每次重新 prompt，`cases` 加 `generate` 那套我最划算。

---

最后给不同角色各一句，下周就能试。

**测试**：挑一个快上的需求，让 AI 补十条边界用例，你审到五条有价值的就行。

**开发**：新接口 PR 里顺手加三条异常用例，测试 review 一下就能并进回归。

**产品**：需求里多写「不展示的情况」「异常时怎样」——这真的帮大忙。

---

我小结一下：AI 没让我变懒，是让我少写重复代码、少填重复表格，把时间留给**判断测什么、怎么算过、怎么让大家看见质量**。

后面我有五分钟 Demo，演示补一条异常用例、跑 pytest、看结果。中间随时打断提问。谢谢。
